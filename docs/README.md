## プロジェクト経験

### 2026/06～2026/09: [Notionライクなメモアプリの個人開発](https://github.com/Soseki-Natsume/notion-like-note-app)

#### プロジェクト概要

リッチなメモアプリをシンプルにしつつ重要な機能や UI を残したものを作りたいと考え、開発しました。
設計から開発、デプロイまで実施。

#### 開発した機能

- 新規作成（Create)
- 一覧表示、選択（Read)
- 編集（Update)
- 削除（Delete)

#### 今後追加予定の機能

- リンクを入力された際に判別してクリック可能にする
- ユーザー識別
- 見出し、小見出し追加
- リンク共有

#### 意識した点

- 軽量であること
  - Go, SQLite の使用
- できるだけクリーンな可読性の高いコードを書くこと  
- シンプルであること  

#### 改善点

- 知識不足からデプロイの際ビルドに手間取りました。Dockerfile に関しては 99％AI 頼りだったため、学習による理解が必要です
- コミット粒度がバラバラ。非常に追いづらい履歴となってしまっています。また、無理に英語を使おうとしてメッセージも読みにくくなっています。コミット粒度をそろえることを強く意識する、あるいは強制するためのツールを導入して改善する必要あり
- DB のテーブルが 1 つのみでありせっかくの Web アプリだが DB がリレーショナルではありません。人に見せるものとして今 1 つ弱い点ではありますが、今後のアップデートで改善予定です

### 2025/11～2026/05: 認証認可基盤（電子証明書）および申請管理機能の要件定義・整理

#### プロジェクト概要

官公庁向けシステム刷新プロジェクトにおいて、認証認可基盤（電子証明書）および申請管理機能の仕様整理・ドキュメント作成を担当しました。

#### 役割・体制/自分の担当領域

- 各チーム間の定例会議へ参加し、未決定・曖昧な仕様をヒアリングして言語化
- 業務フローをもとに[BPMN](https://bpm-consortium.or.jp/bpmn/)形式で機能詳細フローおよび機能一覧を作成
- レビュー内容の機能詳細資料への反映とレビュー票（チーム/PJ）の作成・管理

整合性が極めて重要となる認証・申請機能において、要件の抜け漏れを早期に発見・可視化することで、後続の設計・実装工程における仕様不整合や手戻りリスクを未然に防ぐ役割を担いました。

#### 意識した点

- 手戻りを減らす
  - 認識について上長に確認を取っておく
- レビュアーの負担を減らす
  - マクロによるフォーマットチェック

#### 改善点

- プロジェクト途中で参加したために、機能についての理解が浅くドキュメント作成に時間がかかってしまいました。機能についての理解を深めるための時間やレクチャーについて交渉すべきでした。  

### 2025/07～2025/11: 社内向け請求Webアプリケーション開発

#### プロジェクト概要

2025 年 7 月から同年 9 月までは 3 名体制のチームで Web アプリケーションの新規開発を担当し、10 月以降は 1 人で保守および追加機能の開発に従事しました。

#### 役割・体制

新規開発フェーズでは、要件定義・設計・コーディング・進捗管理などをチーム 3 人で分担しながら担当しました。
保守フェーズ以降は、1 人で機能追加・リファクタリング・マニュアル作成などを継続的に実施。

#### 開発した機能

- ID とパスワードおよびセッション変数による簡単なログイン認証
  - 請求書作成、履歴登録・参照
    - 要員から申告された実働時間や営業交通費を入力し、顧客への請求金額を計算し、請求書のフォーマットに出力する機能
    - 請求履歴の編集・削除・検索
  - 要員情報管理
    - 稼働状況や勤務形態、個人情報などの情報の登録・編集・削除・検索
    - 検索時、チェックボックスによる休・退職者の除外が可能
  - 契約情報管理
    - 単価や契約開始日などの情報の登録・編集・削除・検索
    - 編集履歴の削除・検索
  - 顧客情報管理
    - 担当者の電話番号や代表者名などの情報の登録・編集・削除・検索
  - 契約割当管理
    - 要員名や企業名などの情報の登録・編集・削除・検索
    - 割り当て履歴の編集・削除・検索

#### 自分の担当領域
  
- 業務要件のヒアリングから機能の洗い出し、要件定義・設計までを主導
- プロジェクト進捗の管理
- 保守・追加機能の開発およびコードのリファクタリング
- ユーザー向けマニュアルの作成

#### 意識した点

- 対象ユーザー(総務部事務員）への丁寧なワークフローの聞き取り
- 漏れと重複のないユースケースの考慮および要件定義・画面設計
- オブジェクト指向に基づいた適切なクラス設計
- チーム内でのスケジュール・成果物の管理と迅速な報連相

#### 改善点

- セキュリティ向上。パスワードのハッシュ化や外部からのアクセス遮断などが未実装
- 保守性。フレームワークを使用しておらず、コードに統一性がありません。また、リンターやフォーマッターを導入していないため、命名規則が厳格に守られておらず可読性が低いです
